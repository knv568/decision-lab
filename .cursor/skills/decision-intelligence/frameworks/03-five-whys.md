# Framework 3 — The 5 Whys

## Purpose

Toyota Production System technique: ask "Why?" repeatedly until you reach a **structural** root cause, not a symptom.

## Core prompt (reference)

> I have a recurring problem and I need to find the actual root cause. Use the 5 Whys method. Start with the problem I describe. Ask 'Why does this happen?' Then take my answer and ask 'Why?' again. Repeat at least 5 times. Don't accept vague answers. Push me to be specific at every level.

## Question bank

1. Why does [stated problem] happen? _(then chain whys on each answer)_
2. Is that a **cause** or still a **symptom**? How do you know?
3. What would have to change at the **structural** level to stop this recurring?
4. Have you fixed this symptom before? What happened?
5. Who or what **benefits** from the problem staying as it is? (if relevant)

## Pushback lines

- "That's still a symptom — why does *that* happen?"
- "Be specific: which behavior, which incentive, which fear?"
- "Vague answers don't count — what exactly?"

## Capture before leaving

- Full why chain (minimum 5 levels, or fewer with rationale if problem is simple)
- Identified structural root cause
- One fix aimed at structure, not symptom

## Done when

The last "why" points to something changeable and structural, not blame or vagueness.

## Skip rationale examples

- Pure forward-looking fork with no recurring symptom (suggest 2–3 whys on "why am I at this fork?" instead of full 5).
- User confirms skip after rationale.
